# QGIS向けPortolan Catalog Builder 利用手順

## インストール

初期配布版の動作確認環境はWindows x64のQGIS 3.44.13（Python 3.12、GDAL 3.13.2）です。

1. QGISの「プラグイン」→「プラグインの管理とインストール」→「ZIPからインストール」を開きます。
2. `portolan_catalog_builder-0.2.0.zip`を指定します。
3. Portolan Catalog Builderを有効にします。
4. 「プラグイン」→「Portolan Catalog Builder」→「Portolanカタログを作成…」を開きます。

QGIS本体の表示言語が日本語の場合は日本語で表示されます。英語または未対応の言語では英語になります。QGISの言語変更は再起動後に反映されます。カタログ作成にCLIやpipの操作は不要です。詳細検証は別環境で実施する外部作業です。QGIS環境にはGeoParquet対応GDALとPyArrowが必要で、PMTiles出力時には対応ドライバーも必要です。

## 作成の流れ

1. **レイヤー**：出力するレイヤーとCollection IDを指定します。PMTilesは初期状態でオンですが、一括またはレイヤーごとにオフにできます。
2. **出力対象**：全地物、選択地物、表示範囲と交差する地物、表示範囲で切り抜く方法から選びます。範囲はボタンで取得して固定します。未保存編集・フィルター・結合・計算属性は反映されます。
3. **カタログと説明**：名称、説明、作成者、管理者、連絡先、ライセンス等を入力します。ライセンスは`CC-BY-4.0`などのSPDX識別子、または`other`と利用条件URLを指定します。自分と異なる作成者のデータを配布する場合は出典URLも必要です。
4. **属性と地図**：出力対象画面で選んだCollectionの説明・公開列・属性辞書を編集します。Collection単位で共通情報を上書きできます。日時が不明なら空欄にし、入力する場合は`2026-09-16T00:00:00+09:00`などタイムゾーン付きで指定します。
5. **作成**：存在しない新しい出力フォルダーを指定し、「カタログを作成」を押します。
6. **結果**：検証結果、地図、属性表、説明文、ファイル一覧を確認します。PMTilesを出力した場合は「PMTiles地図を開く」でブラウザー表示できます。

入力データの列名が`fid`、`geom`、`geometry`、`bbox`、`geometry_bbox`、`portolan_id`の場合は、公開を外すか出力列名を変更してください。これらは内部処理用の予約名です。

GUIの言語と生成文書の言語は別です。「文書の言語」は英語が既定で、日本語にも変更できます。入力したタイトルや説明文そのものを自動翻訳する機能はありません。

## 出力と検証

GeoParquet、カタログJSON、README、AGENTS.mdは必須です。PMTilesをオフにすると、PMTiles・対応スタイル・それらへのリンクは生成されません。サムネイルは独立した設定です。

成果物の隣の`.build-report`フォルダーには検証レポートを保存します。処理用の`.portolan-build-*`フォルダーは診断用に残るため、確認後にQGISを終了して削除できます。元のGISデータは変更しません。

バージョン0.2.0では、件数・属性・形状の照合、ファイルの読み取り、JSONとローカル参照先などの基本チェックを行います。rashidによる詳細検証は実行せず、検証用のネイティブライブラリも同梱しません。

作成完了画面には「詳細検証は未実施」と表示されます。「詳細検証の手順」ボタンから英語・日本語のガイドを開けます。公開・配布前に、QGISとは別の環境でガイドに従って検証してください。出力先の `VALIDATION.md` にも手順を保存します。「作成レポートを開く」から基本チェックと未実施の検証状態を確認できます。

公開先のCORSやHTTP Rangeの検査は、公開後に別途実施します。プラグインは外部検証の結果を自動で取り込まず、「検証済み」へ自動変更しません。

設定を保存すると、JSONファイルから再利用できます。QGISプロジェクトにも設定が格納されるので、プロジェクトを保存してください。作成後に新しい入力レイヤーを追加した場合は「レイヤー一覧を更新」を使います。

## 対応範囲

ローカルのGeoJSON・GeoPackage・Shapefileと基本的なメモリレイヤーを対象にしています。2次元の点・線・面に対応し、Z/M、曲線、混在型、日付変更線を横断するデータは明示的に停止します。ラスタ・クラウド公開は後続版で対応する設計です。

複雑なQGISスタイルやラベルは、PMTiles出力時に「基本スタイルを使用」を選んでください。GeoParquetは解析用、PMTilesは表示用です。PMTilesには簡略化やタイル境界での分割があるため、測量・面積計算等にはGeoParquetを使用してください。
